# 超禅定时 0.5.0（个人使用版）

## 功能

- 首页集中展示下次启动、超禅时长和每日定时；执行记录、权限、测试工具和版本信息统一收进右上角“设置”。
- “打开超禅”会停留在原生页面，方便修改设置；返回后更新最近读取的时长，不再重复跳出。未读到新值时保留旧值并标明未刷新。
- 默认保留每天 01:00，支持添加多个每日时间，每条可独立编辑、启停和删除；总开关可暂停全部定时。
- 每个开启的定时提前 5 分钟发送系统通知。需允许提醒通知；关闭通知不影响实际启动。
- 新建或恢复的定时若距离启动不足 5 分钟，会尽快提醒；同一次启动不重复提醒。
- 同一时分不能重复添加。升级会迁移旧版时间与总开关，避免重复执行。
- 使用系统精确闹钟；时长沿用禅定空间的超禅设置。
- 可选开启“超禅时长读取”无障碍服务，只读禅定空间首页超禅卡片的时长；展示最近读取的分钟数和读取时间。
- 正常打开本应用首页后自动进入禅定空间首页，确认时长文字稳定后自动返回并更新；无需手动刷新或返回。设置中的“测试与工具”提供“重新读取”用于失败后重试。
- 每次进入只读取一次，自动返回不会重复触发；最多等待 8 秒。用户切换到其他应用时取消，不抢回前台。超禅运行中不尝试刷新。
- 一次性 60 秒测试不会改动每日时间，可单独取消。
- 开机完成并首次解锁、时间/时区变化、应用更新后重新预约。
- 记录最近六条提醒与启动记录；启动记录包含当时锁屏、屏幕交互状态，请求发出不代表系统一定放行。
- 无网络权限，无 Tasker、Shizuku、Root 依赖。定时启动不依赖无障碍服务；时长展示的读取功能由系统绑定可选的只读无障碍服务。

## 使用

1. 安装 APK，打开应用。
2. 允许精确闹钟、悬浮窗和通知权限，并加入电池优化白名单。
3. 保持“定时总开关”和所需时间的独立开关开启，页面会显示最近一次启动时间。
4. 点击“添加定时”增加时间；点击时间修改，单条右侧更多菜单可编辑或删除。
5. 需要测试时先在超禅中选择短时长，再到“设置 → 测试与工具”点击“60 秒后测试一次”。该短测试不发送五分钟提醒。
6. 要显示时长，在“设置 → 权限管理 → 超禅时长读取”中开启无障碍授权。以后正常打开本应用首页会自动读取并返回。
7. 点击“打开超禅”可停留在原生页面修改时长；修改后回到原生首页，让时长显示出来，再返回本应用即可更新卡片。

## 边界

- 当前版本针对本机的 com.oneplus.brickmode 16.7.3 启动入口。
- 系统或超禅更新可能需要重新适配。
- 强行停止应用后，应重新打开应用恢复预约。
- 重启后尚未首次解锁的场景不在本版支持范围。
- 应用不修改超禅时长，也不修改或解除系统锁屏。
- 展示值是最近一次可见页面的读取结果，不代表后台实时查询。自动读取失败、服务尚未就绪、撤销授权或页面改版时保留旧值和读取时间，须以超禅实际设置为准。
- 读取仅适配 com.oneplus.brickmode 的 super_zen_item 内 itemTime，不扫描轻禅卡片、通知、其他应用或数据库；未知格式不猜测时长。

## 独立项目结构

- `src/com/hujia/zenalarm/`：应用 Java 源码。
- `res/`、`AndroidManifest.xml`：资源、组件和权限配置。
- `tests/`：纯 Java 时间边界测试。
- `build.py`：本地构建入口，不依赖 Gradle。
- `AGENTS.md`：贡献指南；`verification*.txt`：历史验证记录。
- `build/`、`dist/`、`.signing/`：分别存放构建缓存、APK 和本机签名密钥，均被 Git 忽略。

## 构建与安装

需要 Python 3、JDK、Android API 36 平台包及 Build Tools 36.0.0。
在项目根目录执行：

```sh
python3 build.py
adb devices
adb -s <serial> install -r dist/zen-alarm-v0.5.0.apk
adb -s <serial> shell am start -n com.hujia.zenalarm/.MainActivity
```

构建会运行六项时间边界检查，编译、对齐并签名 APK，然后校验签名。
APK 文件名从 `AndroidManifest.xml` 的 `versionName` 自动生成；升级版本后相应调整安装命令。

SDK 默认取 `ANDROID_HOME`，其次取 `ANDROID_SDK_ROOT`，最后取 macOS 的 `~/Library/Android/sdk`。
使用其他安装布局时，复制 `build.local.example.json` 为 `build.local.json`，填写实际 SDK 路径。
本机已配置现有 SDK，可直接构建；搬到其他电脑后重新配置 SDK 即可，源码不依赖原工作区的目录层级。

| 配置项 | 环境变量覆盖 | 默认值 |
| --- | --- | --- |
| `build_tools` | `ZEN_BUILD_TOOLS` | SDK 下的 `build-tools/36.0.0` |
| `android_jar` | `ZEN_ANDROID_JAR` | SDK 下的 `platforms/android-36/android.jar` |
| `build_dir` | `ZEN_BUILD_DIR` | 项目内 `build/` |
| `keystore` | `ZEN_KEYSTORE` | 项目内 `.signing/personal.jks` |

环境变量优先于本机 JSON 配置，相对路径基于项目根目录。`build.local.json` 不入库，示例配置可入库。

## 签名与版本管理

当前机器沿用此前的个人签名密钥，保存在 `.signing/personal.jks`；请单独备份，不提交到 Git。
新环境若未提供原密钥，构建脚本会生成新的个人测试密钥，生成的 APK 将无法覆盖旧签名安装。
覆盖升级前应恢复原密钥，或通过 `ZEN_KEYSTORE` 指向它。

`.gitignore` 排除构建缓存、APK、签名密钥、本机配置和诊断材料。Git 仅管理源码、资源、脚本及文档。
本项目先在本地维护；配置远程仓库和推送须由用户明确授权。
